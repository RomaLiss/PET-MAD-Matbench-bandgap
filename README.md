# bandgap — предсказание ширины запрещённой зоны

Модель принимает кристаллическую структуру и возвращает ширину запрещённой
зоны в электронвольтах. Поверх предобученного энкодера PET-MAD.

**Точность:** MAE 0.1267 эВ на 21 223 материалах тестовой части фолда 0
Matbench `mp_gap`, которых модель не видела при обучении.

> **Только Linux.** На Windows не работает из-за ошибки в чужой библиотеке —
> подробности в конце файла. На Windows годится WSL.

## Установка

Нужен Python 3.10 или новее. Проверено на 3.10 и 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .                 # только предсказание
pip install -e ".[train]"        # если нужно ещё и обучать
```

**Займёт около 7 ГБ и примерно десять минут** (замерено на чистой установке).
Столько весит `torch` с библиотеками CUDA: их тянет `metatrain`, причём даже
если считать собираетесь на процессоре. Отдельно ставить процессорную сборку
`torch` бесполезно — `metatrain` переустановит обычную поверх.

Версия `upet` в зависимостях закреплена жёстко (`==0.1.2`) — это не
перестраховка, при другой версии веса не загрузятся. Причина в `model/VERSIONS.txt`.

### Скачать веса

В репозитории их нет: файл 115 МБ, а GitHub не принимает больше 100 МБ.
Лежат в релизе:

```bash
gh release download v1.0.0 --repo RomaLiss/PET-MAD-Matbench-bandgap --dir model/
```

Без `gh` — со страницы
[релиза](https://github.com/RomaLiss/PET-MAD-Matbench-bandgap/releases/tag/v1.0.0),
файл `fold_0_best_S2_mae.pth` положить в папку `model/`.

## Предсказание

```bash
python3 tools/predict.py структура.cif
```

Или из кода — две строки:

```python
from bandgap.inference import BandgapPredictor
from ase.io import read

predictor = BandgapPredictor()             # собрать модель ОДИН раз
gap = predictor(read("структура.cif"))     # эВ
```

Список структур считается одним батчем: `predictor([atoms1, atoms2])`.

Читается любой формат, понятный ASE: CIF, POSCAR, xyz и другие. При первом
запуске энкодер PET-MAD (26 млн параметров) скачивается с HuggingFace — нужен
интернет; дальше берётся из кэша `~/.cache/huggingface`.

Видеокарта не нужна: по умолчанию считает на процессоре, одна структура —
около секунды. С картой: `--device cuda`.

**Проверочное значение.** Точно такой скрипт должен дать **0.5252 эВ**:

```python
from ase.build import bulk
from bandgap.inference import BandgapPredictor

print(BandgapPredictor()(bulk("Si", "diamond", a=5.43)))
```

Если число другое — окружение собралось не так, как нужно.

**Важно: результат зависит от ориентации ячейки.** PET-MAD не инвариантен к
поворотам по построению (авторы называют его unconstrained), симметрии он
усваивает из данных приближённо. Тот же кремний, записанный в CIF и прочитанный
обратно, даёт 0.6454 эВ вместо 0.5252 — ASE при чтении пересобирает ячейку в
стандартном виде, то есть поворачивает кристалл. Расстояния между атомами при
этом совпадают до шестого знака, кристалл физически тот же.

Расхождение 0.12 эВ сопоставимо с собственной ошибкой модели (0.1267 эВ), так
что учитывайте это при сравнении результатов. Если нужна устойчивость к
поворотам, в `upet` есть усреднение по ним (`rotational_average_order` у
`UPETCalculator`) — здесь оно не используется.

## Обучение

```bash
python3 experiments/matbench_mp_gap.py --folds 0 --name proba
```

Один фолд — около 11 часов на RTX 3090, из них вторая стадия занимает почти
всё время. Все пять фолдов — без `--folds`. Нужно **не меньше 16 ГБ
видеопамяти**: пик второй стадии 14.1 ГБ.

Поменять любой параметр, не трогая файлы:

```bash
python3 experiments/matbench_mp_gap.py --set stages.s2.epochs=100
```

Опечатка в имени параметра вызовет ошибку, а не молчаливое игнорирование.

**Долгие запуски — только в tmux**, иначе обрыв связи убьёт прогон.

Результат каждого запуска — в `runs/<дата_время_имя>/`: метрики по эпохам,
чекпоинты, снимок конфигурации, перехваченный вывод.


## Почему не работает на Windows

`metatrain 2026.1` разбирает путь к файлу как URL. На Windows буква диска
`C:` принимается за схему вроде `http:`, и библиотека пытается скачать
локальный файл из интернета:

```
URLError: <urlopen error unknown url type: c>
```

В `metatrain 2026.4` это исправлено, но перейти нельзя: та версия идёт
в комплекте с `upet 0.3.0`, который меняет имена параметров модели, и
существующие веса в неё не ложатся. Одновременно и то и другое пока
недоступно.

На Linux ошибка не возникает — там в путях нет букв диска.
